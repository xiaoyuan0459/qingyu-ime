# ADR 0002：用户备份版本与恢复事务

状态：已采用（2026-10-08）。实现位于 imesdk。

## 背景

QA-20261008-02 证明旧导出遗漏当前 `files/rime-data/user`。旧恢复直接覆盖打开的 SQLite、偏好与词库文件，也没有完整性校验或中断恢复边界。

## 决策

- ZIP 格式 2 在原有 metadata 四个字段上增加 `formatVersion=2`、根目录清单、每个文件的 SHA-256。四个根为 `shared_prefs`、`databases`、`external`、`rime-user`；空目录也有替换语义。路径由应用提供，归档不能指定目标。
- 导出与数据库写队列串行，先等待偏好落盘、SQLite WAL checkpoint，再关闭 Rime 刷新用户词库。复制完成后恢复原方案。引擎和数据库不能在复制期间写这些目录。
- 导入先限制解压后的总量（512 MiB）、条目数（10,000）与 metadata 大小（2 MiB），拒绝越界、重复、未知路径、未知格式、错误应用或更新版本的备份。完整文件清单和 SHA-256 全部通过后才准备目标同盘临时目录。
- 恢复关闭数据库与 Rime，用同父目录 rename 保留原目录并安装新目录。开始替换前同步写入不可变 `state.json`；所有目录安装成功后同步创建 `complete` 标记。分开的提交标记避免跨平台覆盖已有 journal 文件的差异。
- 提交前异常或进程中断回退所有根；提交后保留新数据并清理旧目录。启动时先恢复，随后才打开偏好、数据库和引擎。批量删除由后台执行。此保证针对进程中断，不宣称覆盖断电、存储介质损坏或目录 fsync 的所有情形。
- 已有有效 `complete` 标记时，不再解析回退记录。未提交且记录损坏、超限或根目录无效时，不猜测缺失的恢复状态；保持当前数据不变，将 journal 与旧／新副本分别在原父目录隔离，避免跨存储卷移动及后续清理误删。启动提示重新导入完整备份。隔离副本仍属于当前应用用户，不自动删除；无有效记录时不能保证各根来自同一版本。
- 成功导入后写队列拒绝新写入并要求重启。Android 偏好、数据库快照与引擎缓存必须由新进程读取。

## 兼容与边界

无 formatVersion 的旧 ZIP 按格式 1 读取。只替换旧备份实际包含的根；当前用户词库目录保持原样，界面明确提示旧备份缺项。新版不生成旧格式，不双写旧路径。普通、离线 debug / release 的轻语包名属于同一兼容家族；仍拒绝高于当前 versionCode 的导入。

备份包含本地历史、常用语、置顶、设置、外部私有素材及当前用户词库。导入的第三方 Rime 资源包位于独立 pack store，用户需保留原始包并在新设备安装相应方案；日志、缓存、APK 与系统权限授权不属于用户备份。哈希校验用于发现损坏，不作为来源签名或加密。

归档没有安装远程内容、账户或同步能力。恢复工作目录与数据始终属于当前 Android 应用用户；所有测试夹具使用合成数据。

## 验证

`UserDataArchiveTest` 从公开归档 / 文件系统边界检查：新版用户目录往返与陈旧文件移除、旧格式保留用户词库、篡改 / 缺项保留所有原根、危险路径拒绝、metadata 拒绝，以及持久 journal 的混合中断回退和重复恢复。

损坏记录回归在修复前复现两个解析失败：未提交损坏记录阻断启动、已提交恢复仍因损坏记录失败。修复后检查截断 JSON 与未知根不会阻断重复恢复，当前数据与所有副本保留，之后可重新导入；已提交的损坏记录不影响已安装数据。文件系统无法执行 rename 时仍明确报告失败并保留原记录，不声称覆盖存储设备故障。

设备上的导出、重启与恢复验证另记入[数据与隐私](https://github.com/xiaoyuan0459/qingyu-ime/wiki/Data-and-Privacy)。真实低存储、断电与各厂商文件系统行为列为发行前验收边界。
