# ADR 0004：整体 GPL-3.0-only 开源路线与上游许可义务

状态：已采用（决策于 2026-09-20；论证补记于 2026-10-14）。适用范围为全仓库许可策略，第三方的逐项登记与待办见 [LICENSING.md](../../LICENSING.md)。

本 ADR 保留许可路线的决策依据与已核实事实，防止后续改动把论证当成可推翻的偏好。它是工程内部审计记录，不构成法律意见。

## 背景

项目由 YuyanIme 的 Android 输入框架迁移而来，后续要自研原生层、重编词库并公开发布。评估的核心问题是：自研并改动 librime 之后再开源，许可上是否成立。

结论是不能按 BSD-3 单独开源，原因不在自有代码，而在随包分发的词库与继承代码的来源。

## 已清除的阻断项

原 `libs/pinyin4j/ResourceHelper.java` 文件头写明 GNU GPL（GPL-2.0-or-later），且整份源码拷入仓库而非外部依赖，构成明确衍生作品：只要 APK 含它，整个应用就必须按 GPL-2.0+ 分发。

处置（2026-09-19 完成）：不引入第三方拼音库，改走自研小工具加 MIT 数据表。数据取 [pinyin-data](https://github.com/mozillazg/pinyin-data) v0.15.0（MIT），由 `tools/gen-pinyin-table.py` 生成 `assets/pinyin_table.txt`（26711 字，带声调，首部内嵌 MIT 声明），查询走 `HanziPinyin.kt`。同时删除 `libs/pinyin4j/` 与无代码引用的 `assets/pinyindb/`。

核验：`libs/` 现仅剩 `cropper`、`expression`、`recyclerview` 三个待补署名的移植目录，无 pinyin4j；APK 含 `pinyin_table.txt` 而无 `pinyindb/`。

## 词库数据源是 GPL-3.0

用 GitHub license 接口实测上游，结论是词库直接触发 copyleft：

| 上游 | SPDX（实测） |
| --- | --- |
| `rime/librime` | BSD-3-Clause |
| `mozillazg/pinyin-data` | MIT |
| `iDvel/rime-ice` | GPL-3.0-only |
| `gaboolic/rime-frost` | GPL-3.0 |
| `osfans/trime` | GPL-3.0 |
| `fcitx5-android` | LGPL-2.1 |

`*.table.bin` / `*.prism.bin` 由 `*.dict.yaml` 编译而来，属派生作品，随 APK 分发即触发 GPL-3.0 的对应源码义务，且不得附加比 GPL 更严的限制。rime-ice 的 LICENSE 自初始提交（2022-10-30）起即 GPL-3.0-only，没有可利用的宽松期，不能标成 BSD。

## 上游 BSD-3 与整包许可不是一回事

上游 `gurecn/YuyanIme` 于 2026-06-15 由作者本人提交 `84a00c6 fix(doc):修改开源协议声明`（`yuyansdk/LICENSE` 同提交一并更换），把 LICENSE 从 GPL-3.0 全文换成 BSD-3-Clause。这不构成整包许可的推断依据，需要分开读：

| 内容 | 许可 |
| --- | --- |
| Yuyan 自有源码 | BSD-3-Clause |
| librime 引擎 | BSD-3-Clause |
| 上游预编译 `libyuyanime.so` | 不适用 BSD-3，另有技术与商业授权条款 |
| 若实际分发 rime-ice / rime-frost 派生数据 | 该数据及派生物仍须遵守 GPL-3.0 |

GPL 代码或词库不会因为仓库根放了一份 BSD `LICENSE` 就变成 BSD。本项目因此不把 README 鸣谢当作许可证证明：每个随 APK 分发的词库和二进制都必须有来源、revision、SHA-256、SPDX 和可重建说明；无法证明来源的继承二进制宁可移除。

作者有权改协议，是因为版权人不是自己作品的被许可人：已授出的 GPL 许可不可撤销，但版权所有者保留未授出的权利，可再以其他条款提供同一份代码。前提是他有资格处置全部版权 —— 实测改协议时点的 159 条提交全部出自 `gure <gurecn@163.com>` 一人（`heart258`、`晓潇筱枭` 的提交均在改协议之后，受 BSD-3 约束），仓库内无 CLA / DCO，故该变更合法且干净。

## JNI 绑定层的来源不确定性已用重写消除

继承的 JNI 绑定类原名 `…inputmethod/core/Rime.kt`，与 Trime 的 `com/osfans/trime/core/Rime.kt` 同类名、同 `core` 子包约定，16 个 native 方法中 12 个与 Trime 逐字同名，`selectRimeSchema(schemaId: String): Boolean` 签名完全相同。判读为从某个旧版 Trime fork 后各自演化。Trime 的 LICENSE 提交史含一条 2016-11-17「更改協議」，改动前协议不明：若当时是 GPL，这部分代码的 BSD-3 主张站不住。

解法是不追溯、直接重写：`Rime.kt` + `Structs.kt` 仅 16 个方法 / 8 个数据类，按语义命名重写为 `RimeSession` / `EngineTypes`（`com.qingyu.inputmethod.core`），绑定层两侧由本仓库定义，Trime 痕迹与该许可不确定性一并消除。该项已完成，见 [原生层接口契约](../../imesdk/docs/自研native层接口契约.md)。

## 决策

原三选一：清掉 GPL 依赖后按 BSD-3 开源、整体按 GPL-3.0 开源、只开源自研原生层而应用闭源。选定 **整体 GPL-3.0-only**，即以持续提供完整对应源码为代价换取直接使用成熟词库。

### 2026-10-14 复核：维持，不改Apache-2.0

曾评估改为 Apache-2.0（同样满足「允许使用、必须署名、允许商用」），结论是**不可行**，原因是内置词库：

| 事实 | 证据 |
| --- | --- |
| 雾凇 rime-ice 为 GPL-3.0-only | pack `manifest.json` 的 `license.spdx` |
| 编译产物打进 APK | `assets/rime-base.zip` 36,769,255 字节，内含 17 个 `.prism.bin` / `.table.bin` |
| 首次启动强制装载 | `RimePackManager.ensureBuiltinInstalled` 在无 pack 时直接解压内置包 |
| 由 librime 运行时读取 | `sharedDataDir` 指向 pack 目录，引擎从该目录加载 |

GPL-3.0-only 与 Apache-2.0 **单向不兼容**：Apache 代码可进 GPL，反之不行。因此只要词库继续内置，
整体就必须是 GPL-3.0-only。

**已评估并放弃的替代路径**：

- 把词库移出 APK 改为用户导入 —— 破坏离线开箱即用；且重写自有词库的维护成本高、基础体验难以追上成熟词库
- 代码 Apache-2.0 + 词库以独立 GPL 进程 / IPC 隔离 —— 架构改动大，且仍可能被认定为整体作品而须整体 GPL

注意：本项目选 GPL-3.0-only **不是因为它更宽松**。两者都要求署名、允许商用；差别在于 GPL 额外要求衍生作品同样开源。
若日后确有业务需要放宽，唯一干净的路径是更换为非 GPL 许可的词库来源，再整体转 Apache-2.0。
YuyanIme 的 BSD-3 署名义务与此独立，改根协议也不能免除。

| 分发单元 | 内容 | 许可 |
| --- | --- | --- |
| APK | `app/`、`imesdk/`、自研 JNI、librime、默认雾凇运行时 pack | GPL-3.0-only + 第三方声明 |
| 默认 pack 对应源码 | 固定 revision 的 rime-ice / rime-essay、装配清单与构建脚本 | 与 APK 同时提供获取入口和精确校验信息 |
| 用户可选 pack | 白霜等 GPLv3 兼容 Rime 数据，独立 pack，不进 APK | 独立 manifest、版本、许可证和来源 |

配套要点：默认 pack 固定 rime-ice commit `9e66b0729083b37d217312294f6d516c8d7234be`，manifest 记录 SPDX、revision、SHA-256 与源码入口；`tools/build-rime-pack.py` 校验上游 revision 与 essay 哈希。`qingyu_deployer` 编译词库本身不产生 GPL 义务，但编译脚本与 `dict.yaml` 源属于 pack 的对应源码，分发时必须一起给。

保留项：librime 等 BSD 上游声明继续保留，不被根许可证抹除。

## 参照上游的使用边界

GPL 项目可以进入本 GPL 应用，但须做到来源明确、许可兼容、归属完整、可重建。

| 上游 | 可以 | 不可以 |
| --- | --- | --- |
| 同文 Trime（GPL-3.0） | 读方案：九宫格候选组织、键盘布局的描述式配置思路、方案切换交互 | 抄 `Rime.kt`、键盘/主题 Kotlin 代码、`*.yaml` 配置（配置同属 GPL 作品） |
| fcitx5-android（LGPL-2.1） | 读架构：引擎与 UI 的进程/插件边界、输入面板抽象 | 直接取 Kotlin/C++ 源码 |
| rime-ice（GPL-3.0-only） | 默认词库，编译产物随 APK | 浮动引用、不提供对应源码、删除许可证或修改记录 |
| rime-frost（GPL-3.0-or-later） | 制成独立可选 pack 分发，固定 revision `96278d8`，方案 id 与雾凇包对齐 | 与雾凇混成无法追溯的单一词库；解进 APK |
| OpenCC（Apache-2.0） | 随包分发转换数据，保留 LICENSE 与 AUTHORS | 去掉声明；虚构上游未提供的 NOTICE（该固定 revision 确未提供 NOTICE） |
| librime（BSD-3） | 静态链入、按需 gear 扩展 | 去掉版权声明 |
| pinyin-data（MIT） | 生成表随包分发 | 去掉文件头的 MIT 声明 |
| rime-stroke（LGPL-3.0-or-later） | 五笔画词库，固定 revision `1e8fff9b` 编译进默认 pack | 去掉 CNS11643 / 北大论坛的归属声明 |
| Yuyan | 代码参照：Android `InputMethodService` 接线、键盘视图、设置页结构 | 作为产品/设计规格来源（2026-09-20 起退出参照位） |
