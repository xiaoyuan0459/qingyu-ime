# 相邻键纠错的切分权重

日期：2026-10-21。状态：已采纳。相关：[DEBT-CORRECTION-01](../TECHNICAL_DEBT.md)、
[性能与内存](https://github.com/xiaoyuan0459/qingyu-ime/wiki/Performance)。

## 背景

26 键全拼把相邻键误触的变体预先写进棱镜，让 `xhong` 能出「中」。这些变体原先使用
`derive/^S$/V/`，类型是 `kNormalSpelling`，与精确拼写同权。`yuanl`（`yuan` + 简拼 `l`）
因此会被引擎切成 `yua'nl`（`yua`←`hua`、`nl`←`ni`），首屏变成「华丽」，精确的「原来」
反而没有机会出现。九键用分词键输入 `yuan'l` 时切分明确，不受影响。

尝试过但不足以保证正确性的方案：

- 把纠错规则改成 `fuzz`：`kFuzzySpelling` 仍排在 `kAbbreviation` 之前，`yuanl` 依旧
  输给纠错切分；
- 打开 librime 内建 corrector：纠错变体被标成 correction，但候选仍按词频混排，
  `song` 会让「动/定/东」压过「送」，且 4 条上限仍在；
- 只在同一终点有完整音节时剪掉纠错：`xhong` 的首段是简拼 `x`，没有完整音节可让，
  纠错会被错误保留/排序，行为不稳定。

## 决策

在 vendored librime 中增加一个独立拼写类型 `kCorrectionSpelling`，位置在
`kAmbiguousSpelling` 之后、`kInvalidSpelling` 之前，保留旧 prism 的
`kCompletion` / `kAmbiguousSpelling` 数值，并新增代数规则 `correct/x/X/` 生成该类型。
音节图构建完成后执行统一策略：

1. 若从输入起点到最远位置存在一条「首段是完整音节、后续不含纠错」的通路，删除图中
   所有纠错拼写。`yuanl`、`song`、`nih` 等走这条：精确/简拼路径保留，纠错切分让位。
2. 否则把纠错拼写降为 `kNormalSpelling`、credibility 归零，让 `xhong`、`shong`、
   `wpman` 这类只能靠纠错的输入仍按原词频正常出候选。

策略只处理 `correct/` 规则和（若开启）内建 corrector 的纠错边；模糊音、简拼和正常
拼写不受影响。补丁以 `tools/patch-librime-correction-type.py` 形式幂等重放，由
`imesdk/src/main/cpp/qingyu_rime/CMakeLists.txt` 在编译 librime 前调用；vendored 的
librime 本身不入库。

## 结果

同一份内置词库实测：

| 输入 | 结果 |
| --- | --- |
| `yuanl` | 组合串 `yuan'l`，原来 / 原理 / 原料…；无「华丽」 |
| `xhong` | 中 / 从 / 种…，纠错仍生效 |
| `shong` | 中 / 从 / 种…，纠错仍生效 |
| `wpman` | 我忙 / 我蛮 / 我慢…，纠错仍生效 |
| `song` | 送 / 松 / 宋…，精确输入不受打扰 |
| `zong`（模糊音开） | 中 / 种 / 重 / 总…，模糊音顺序不变 |
| 联想 `yuanl` | 原来 / 原理 / 原料… |
| 九键 `yuan'l` | 远离 / 原来 / 原理…，与原行为一致 |

设备回归与 instrumentation 用例见性能记录第 16、18 项和 `CorrectionSegmentationEngineTest`。

## 代价与升级约束

- 这是对 librime 的小范围源码修改（BSD-3-Clause 允许），不再是 pristine 上游；补丁脚本
  是唯一事实来源，升级 librime 时必须先应用并重跑上述差分。修改只增加类型/规则，
  不改变上游数据格式。
- 纠错表仍需与 `pinyin.schema.yaml`、`associate.schema.yaml` 的 algebra 同步，重新生成/
  打包含内容版本摘要，旧包会被重装。
- 双拼、笔画等没有本策略所需读音→键码通路的方案不参与；它们保持原有切分和排序。
- 新 pack 的纠错拼写类型使用新增数值；旧版本应用不能读取新 pack，词库包与新 lib 必须
  一起随 APK 升级。旧 pack（类型数值仍是 completion/ambiguous）在本次补丁下保持可读，
  已用旧 frost pack 复核 `yuanl/nihao/zong` 正常。
