# 0012：生成前拼写策略与有界整词纠错

日期：2026-11-03。状态：实现与验收中，采用结论以本批配对回归记录为准。

## 问题与边界

关闭模糊音后，SDK 原来只删除原生候选中不允许的读音；这些读音已经参与音节图、
纠错剪枝和最优整句搜索。事后过滤无法恢复被它替代的句子，全键和九键都有影响。
另有跨音节转置、重复字母等错拼无法通过逐音节纠错恢复完整词。

本次保持基础词库包、权重和持久化格式不变。不会将参考输入法的答案、词表或样本
注入运行时。开发样本的改进不代表独立留出收益，也不代表整体达到参考输入法。

## 决策

固定 librime 源码增加窄范围的 `Syllabifier::SetSpellingFilter` 与
`ScriptTranslator::AllowSpelling` 接口。`tools/patch-librime-spelling-policy.py`
先检查锁定 revision 与所有源码锚点，再写入；重复运行保持字节不变。

具体策略由 `qingyu_rime/spelling_policy.cc` 实现，在音节图边准入前按字典的真实
音节及用户启用的四组模糊音检查 fuzzy/abbreviation 边。正常、补全和原有纠错边仍走
原规则；双拼、笔画、联想不启用该策略。缓存仅保存字典音节及派生形式，不保存输入。
SDK 的末端拼写校验继续保留，未知自定义音节无法解码时仍由该边界处理。

全键输入为合法读音的未完成前缀时，仍须保留补全：`zhon→zhong` 的棱镜边可能标为
fuzzy，不能因此在 nasal 关闭时删掉。当前字典的规范音节与基础别名用于区分未完成
前缀和完整的 `lan`；后者仍拒绝 nasal 关闭时的 `lang`。此规则不应用于九键键码。
这一增量输入回归在原型中已复现，并由现有模糊音设备用例覆盖。

全拼主字典另由 `word_correction.cc` 有界探查完整词，使用实际词典及原译器查询：

- 输入限小写字母 4–16 位，最多 32 个相邻转置、重复字母删除或鼻音 g 补入变体。
- 保护原本完全拼写的词/句及非重复的合法简拼；每变体最多检查 16 个原生候选。
- 只接受与变体规范读音完全一致的 2–4 字词典词；拒绝整句及第二次模糊/简拼/纠错跳转。
- 最多加入 6 个候选，保留原候选池、原词的学习信息以及原始输入的消费范围。
- 稀疏的独立繁体字典不做此恢复，避免替代有效的原词简拼；主字典的原字旁路保留。

此整词恢复不作用于九键；九键本次收益来自生成前拼写准入。更广的九键错码、缺键和
整句搜索仍需独立工作包，不以改变词频或开发答案特判补齐。

## JNI 与生命周期

`RimeSession` 缓存模糊音掩码及纠错开关，启动和切方案后重新设置原生选项。
`Candidate.isSpellingCorrection` 是实际候选来源信息，由 JNI 跟随 shadow 和去重候选
传回；SDK 可据此保留合法整词恢复，并在纠错关闭时拒绝该来源。所有展示、翻页、
选择仍使用原生 `engineIndex`，不使用过滤后的展示下标。

候选类受 `@Keep` 保护，新增字段与 JNI 同版交付。升级旧 APK 不迁移词库和设置；
回退代码会失去生成前控制及整词恢复，但不改变用户库格式。已有禁止学习保护仍按
[ADR 0011](0011-禁止学习标记与中文组合分离.md) 执行。

## 构建兼容

修复旧纠错补丁生成器与实际 vendor 枚举顺序不一致的问题：`completion=3`、
`ambiguous=4`、`correction=5`，保持现有 prism 数值契约。已打补丁但顺序不兼容时
构建直接拒绝，避免静默复用错误类型。相关脚本均加入 CMake 配置依赖。

## 验证与风险

行为回归由现有模糊音和纠错设备测试负责，覆盖真实原生候选、来源、选择、退格重输、
纠错关闭和繁体合法简拼。SDK 测试使用独立测试包与可恢复的临时用户目录。

原生全输入回放与 SDK 可见文字回放是不同口径；旧 SDK 无法导出候选消费范围，不能
把可见文字命中伪装成原生完整消费召回。工具比较须绑定实际 APK/探针、词库字节、
夹具、选项、设备和候选窗口。分组退步预算保持冻结，保留失败原型报告。

尚需完整配对质量、同机交替计时与实际应用两种键盘的验证结果后作采用决定。

## 2026-11-04：保留已有合法候选

完整开发集发现，仅检查原生第一项会漏掉被禁用模糊音候选挡在后面的合法词；
整词恢复因此可能把 `wanshan` 的“完善”换成“望山”，或压过原有的逐音节纠错。
恢复前现有首屏（最多 30 项）按同一拼写准入规则检查，并原序重放已探查候选。
保留合法完整词，以及首个合法的多音节部分词，防止把仍可选择的“对象”替换掉。
重复字母输入仍允许修正有歧义的简拼，已经完全拼出的规范词继续受保护。

生成前重试也保留首个合法的非重复多音节词。独立的稀疏繁体字典暂不启用新图边策略，
沿用原搜索与 SDK 末端过滤，避免新造句抢过主字典的合法原字旁路。主字典的生成前
重试及整词恢复保留；这不是改变字形权重或对开发答案作特判。

回归在 SDK 的真实输入、展示、原生下标选择边界上验证。测试使用新用户库，同时
归一并恢复字形偏好，避免 `Kernel` 切方案时重施持久设置，或“总”的历史学习状态
掩盖测试前提。原生未过滤页的首项不再作为 SDK 展示顺序的重复断言。

旧版完整结果虽已从真机取回并核对冻结字节，主机缺少最终 instrumentation 状态，
仅作拒绝旧原型的诊断证据，不能补写成完整通过收据。新包的质量与采用状态另见本地
`docs/testing/2026-11-04-S2真机回归/README.md`；设备回归通过不代替质量或性能验收。

## 2026-11-05：验收出口与采用限制

最终冻结包与基线在同一 arm64 真机各完成 9,900 例 SDK 可见文字回放。分组门禁通过，
原有首选没有丢失；但两个错拼在简体、原字下仍有四处候选名次退步，不能据此声称
个例全部零回退。五轮交替原生计时中，18 个分列有两个超过预先冻结的 10% 探索预算。

当前保留实验状态，不作整体采用或发布结论。下一步分别核对整词恢复和新重试流的
顺序、延迟短码路径中的音节全集构建，以及减少长句重试的重复字典检索。真机 CPU
采样是定位依据，不是改进已成立的证明；后续源码改变须重新冻结产物并复验。
完整矩阵、四处退步、两列性能失败及保存审计仍见上述本地真机报告。

## 2026-11-05：重复错拼与查询成本续作

重复字母输入中的普通纠错词不再阻断整词恢复，只有规范读音与原输入完全相等的词受保护。
鼻音位置补充 g 的相邻键替换，仍共享 32 次变体、每次 16 项及最多 6 个输出的原有边界；
只接收真实词典里的规范完整词，不作答案特判。重复字母先对原词流做整词恢复，避免被
后续合成句路径遮挡；其他输入保持先原搜索 / 必要的严格重试、再整词恢复，避免把本来
能由重试直接得到的完整词提前展开成多次词典查询。

完整音节判定改用译器初始化时显式准备的只读有序音节索引，各译器复用该索引。按键时只查询音节
及既有别名，不再重建音节全集，也不重复运行拼写匹配；仍区分合法补全与禁用的完整模糊音。
索引只含词典音节，重建表时失效；装载成本与按键耗时分别记录，不作为触摸显示时延。

`tools/patch-librime-table-cursor.py` 在锁定版本上复用有序树节点查找位置，并提供显式音节
索引准备接口。只有拼写准入译器调用该接口，不对无关的英文词典等建立索引；准备过程用互斥
保护，查询只读，重新装载或重建表会失效。不改变表格式、词频、候选排序或学习协议。
补丁的版本、锚点、幂等与实际 vendor 一致性均须验证。测量结果及剩余限制见本地
`docs/testing/2026-11-05-S2候选恢复与性能/README.md`，本段不代替整体采用决定。

## 2026-11-06：全键单漏字母恢复与精确词条查询

F01 在主全键译器中增加单漏字母状态图，只使用实际词典的规范音节和存在的词条码。
输入限定 4–16 个小写字母、恢复词限定 2–4 音节 / 汉字；图边最多 4,096，字典结果最多
检查 512 项。它与旧整词恢复共享 32 次查询、每次最多 16 项和合计 6 个恢复输出。
译器初始化准备音节首 / 次字母索引，缓存不含编辑内容；词典不可用或超限时保留原流。

规范词、合法简拼和启用的完整模糊拼写继续保护；未完成音节前缀不能冒充完整模糊写法。
已有可接受的末音节补全可复用，关闭的模糊音不构成提前退出依据。合成句保留合法首选。
恢复项按现有质量排列规范码，每码先给两个词形，再按原质量回填，避免一个码的同音词
占满恢复槽位；不改默认频率，不按目标词或领域设例外。

逐例审查发现，含相邻重复字母的输入会因上述分组挤掉旧删除恢复的同音词；这类输入继续
按原词条质量排序，不强制为其他插入解释分槽。无相邻重复字母时保留规范码分组，预算不变。

已有直接尾字母恢复词条时复用该流，不再枚举其他插入路径；这是查询成本与替代解释召回的
有限取舍。查询与输出均有界，不保证枚举全部单错解释，也不从合法原码推断用户意图。

`tools/patch-librime-exact-words.py` 在锁定 librime 提交上新增 `QueryExactWords`，
由已确认的音节码构建单一路径，再调用原词典 / 用户词典查询与候选准备流程。它只保留
完整词，不再次解析规范拼音、不预测或造句；原 `Query` 不变，用户库禁用规则、词条身份、
原生下标及学习信息沿用原流程。SDK 保留显式整词纠错的原生顺序，普通音节纠错仍按原规则降序。
候选包装使用原输入的 preedit 和消费终点，选择 / 退格由真实 SDK 与 IME 点击流程验证。

补丁先验证固定版本和全部锚点再写入，构建时自动重放；干净源码重放、幂等、锚点漂移、
版本拒绝和生成文件摘要分别核验。不改变词库、持久格式、权限或 ABI 导出接口；撤销本项
增量即可回退。运行质量、性能与失败原型保存在本地 F01 验收卡，源码实现不代表本项已通过。

## 2026-11-06：保留合成句的重复字母恢复

F02 区分真实规范词与自动合成句。含一次连按的输入可能恰好拼成完整句，例如多出的元音
会被解释成语气词；合成句的拼写完整不能据此阻止尝试删重。原句仍先返回，新增分支仅尝试
相邻相同字母删除一次，只接受规范读音与变体完全相同的真实词典词，不把合成句作为恢复项。
真实完整词继续优先，其他既有变体路径保持原行为。

新分支沿用共享查询、候选扫描和输出预算，不新增词频、数据格式、设置、权限或异步工作。
选择仍用原生下标和原输入的消费终点，退格编辑原始错码；无结果时原流顺序不变。
固定排序测试使用隔离用户库并禁学；实际软键盘点击另外验证 InputConnection 上屏。
本地 F02 验收卡记录质量与性能的最终状态，本段不作整体采用结论。

## 2026-11-06：单次相邻换位的精确词码准入

F03 在已有整词 / 漏键恢复之后补充相邻换位。原保护会因局部词、简拼或合成句停止旧变体查询，
这些解释应保留，但不等于用户没有单次换位的意图。新层先核对首项和真实精确词码；无恢复项
直接返回原流，有恢复项才扫描原解释，避免为了不存在的词额外推进候选和重复做拼写准入。

`AdjacentTranspositionRecovery` 用未编辑、已换位、跨音节边界待接首字母的状态构建音节图。
已编辑状态只能继续精确音节，不允许第二次编辑；不能到达一次换位终点的分支在查词前移除。
图边最多 4,096，字典检查最多 512 项，词码限定 2–4 音节。只对实际存在且规范码确为一次
相邻不同字母交换的词调用已有 `QueryExactWords`，不经过造句、简拼、模糊音或第二次纠错跳转。

初始化时保存只读词典音节，候选规范读音复用它；空音节和无效下标保持原 Decode 的失败语义。
缓存不含输入文本，不改变词库、权重、用户库、设置、权限或 JNI 数据格式。旧有显式恢复保持
原顺序，新增查询和输出继续共享 32 / 16 / 6 上限。合法原码、规范别名及用户开启的完整模糊
拼写在新备选前保留，不从歧义码推断意图。

恢复仍包装原始输入和消费终点，选择使用原生下标，退格编辑原错码。同步查词及图的边属性
在本次查询内持有，不复制并独立消费共享游标的词典迭代器；无结果、未装载或超限保留原流。
回退仅撤新层与同版接线 / CMake 源码绑定，无持久数据迁移。质量和性能状态以本地 F03
验收卡及字节绑定收据为准，源码存在不表示已验收或整体采用。

普通完整词和规范前缀补全继续受保护。拼写策略与各恢复阶段会重复遇到相同候选；单次查询
内最多缓存 32 个候选的准入结果，持有候选引用防止地址复用。缓存与固定的输入、字典、
模糊组选项同生共灭，不跨查询保存编辑内容，不改变原判定或词频；超过上限直接重算。

漏键与换位恢复所用的规范音节和首 / 次字母索引由同一译器持有的 `CanonicalSyllabary`
准备一次，两层只读取。保留原漏键索引的内容、顺序和字典身份失效条件，移除原先的重复准备，
不改变漏键搜索图、词典查询和排序。单查询准入缓存仅在全拼纠错开启且输入为 4–16 个小写
字母时启用；其他输入沿用既有判定。临时换位图不保存输入视图，查询结束即释放所有临时状态。
