# ADR 0001：键盘触感按设备能力适配

状态：已采用（2026-09-28）。适用于 Android 版轻语输入法；触感质量仍需真机矩阵验证。

## 背景

同一品牌的不同机型可能使用不同马达、驱动和系统触感实现。仅根据 `Build.MANUFACTURER` 设定毫秒数或振幅，不能可靠代表实际触感。按键输入频繁，长波形容易产生拖尾。此前 RichTap 初始化成功后直接视为已播放，未先检查设备是否支持其播放器，可能在部分机型静默失效。

## 决策

1. 默认“系统”档对普通按键调用 `View.performHapticFeedback(KEYBOARD_TAP)`，回车和长按使用对应的系统动作，由系统和厂商处理触感及用户开关。
2. 自定义三档检查视图开关、系统触感设置和马达，再按能力选择受支持的 Android `PRIMITIVE_TICK` / `PRIMITIVE_CLICK`、Android 16 短包络、可控振幅波形；没有可控振幅的设备用 8 / 12 / 18 ms 短脉冲区分强度。按事件缩放后限制在 6–22 ms，避免长尾。每次按键只走一条路径。
3. 2026-10-07 移除 RichTap 闭源 AAR 和调用，使用 Android 公共接口。预置 EFFECT_TICK 不能接受强度缩放，因此不能作为自定义三档的共同回退；“系统”档仍由系统提供键盘触感。
4. API 33+ 使用 `VibrationAttributes.USAGE_TOUCH`，由系统执行触感开关和强度；较早系统保留 AudioAttributes 与旧触感设置的局部兼容分支。失败或不支持时按能力降级，不新增权限或厂商接口。
5. 按事件区分轻重：普通字符最轻；空格、退格、功能键略重；回车、候选确认和长按更明确。系统档只使用 Android 的动作语义，用户选三档强度时才按事件缩放。触摸按下与长按确认各触发一次，自动重复退格与手势移动不重复触发；两次触感至少间隔 50 ms，防止高频输入叠成持续震动。

## 厂商覆盖与验收

| 设备组 | 运行时选择 | 真机待验证 |
| --- | --- | --- |
| 小米 / Redmi / POCO | Android 公共能力链 | 澎湃 OS 的全局触感开关、三档差异、快速连打 |
| OPPO / 一加 / realme | 同上，按实际马达能力选择 | ColorOS / OxygenOS 的触感开关、拖尾 |
| vivo / iQOO | 同上，按实际马达能力选择 | OriginOS 的触感开关、候选点击 |
| 三星 | 同上；“系统”档始终使用 One UI 提供的键盘触感 | One UI 的系统档、特殊键与连续输入 |
| Google Pixel | 同上，通常由 Android 原生触感能力决定 | 系统档、三档可区分性 |
| 华为 / 荣耀 Android 设备 | 同上；不接入 HarmonyOS 专用接口 | 设备能力与系统触感开关 |
| 其他 Android 设备 | 同一能力链 | 无马达、旧 Android、低端马达回退 |

每组至少测试：系统档、关闭、三档预览；系统触感开关关闭后连打无震动；普通字符、空格、退格、回车、候选点击和长按的轻重；按住退格自动重复时不持续震动；快速连打不出现明显长尾。记录机型、系统版本、马达能力和主观结果后，才考虑加入机型特例。
