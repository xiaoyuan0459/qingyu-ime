# ADR 0011：禁止学习标记与中文组合分离

- 日期：2026-11-02
- 状态：采用
- 范围：SDK 编辑器语义、Rime 会话与内置用户词库写入

## 问题与证据

在全新 Android 15 测试环境对照搜狗时，普通文本框声明
`IME_FLAG_NO_PERSONALIZED_LEARNING`，搜狗仍能将九键 `64426` 转为“你好”，
轻语却直接上屏 `MGGAM`。原实现把 `EditorContext.allowsSuggestions == false`
当作密码框处理，连中文组合也旁路了。

Android 的该标记请求输入法不更新输入历史和个性化语言模型，并不要求禁止中文转换。
它与密码框、`TYPE_TEXT_FLAG_NO_SUGGESTIONS` 的语义分别处理。

恢复中文路由后，设备回归进一步复现：私密框连续选择合成词“史诗”会使其从第 5 位
升到首位。固定 librime 1.11.2 没有可直接复用的 `disable_user_dict` 会话选项；
只设置任意布尔选项并不能保护用户词库。

## 决定

1. 只有密码框继续旁路中文组合；禁止学习的普通文本框保留中文候选、翻页和上屏。
2. 保留 `allowsSuggestions` 对联想、剪贴板提示、输入上下文缓存及手写学习的既有保护。
3. 软键盘 `InputView` 与硬件候选栏 `CandidateView` 在清理旧组合后，依据新编辑框策略调用
   `RimeSession.setPersonalizedLearningEnabled`。它是编辑器临时状态，不写入用户偏好。
4. 会话缓存所需策略，在异步启动、切方案和重启后重新应用；普通编辑框恢复学习。
5. JNI 将策略写入 SDK 控制的 `qingyu_no_learning` 上下文属性，避免与 schema 的
   可切换选项混用。候选生成和已有词库查询保持可用。
6. 构建期幂等补丁在 librime `Memory::OnCommit`、`Memory::OnDeleteEntry` 的写入入口
   检查该属性。私密编辑不创建学习提交，也不删除用户词条；普通状态走原实现。
   独立联想与笔画通配探测也固定设置该属性，替换原先无效的会话选项。

补丁只接受 `tools/native-deps.lock.json` 锁定的 Git revision，校验所有源锚点后才写入。
不更改词库包、用户数据库格式或基础词频，不新建另一套用户库，也不引入双写。
既有个人词库仍可供输入转换使用；本决定保证不由该编辑框更新它。

## 验证与兼容

扩展现有真实触摸测试，覆盖禁止学习框的中文组合/上屏、连续选择不升权、切方案与重启
保持策略，以及返回普通框后确实恢复升权。学习数据在 SDK 测试包的临时用户目录中运行，
结束恢复原测试目录和原默认输入法，不接触实际应用个人词库。

具有硬件键盘的设备另覆盖关闭软键盘后的真实按键、中文上屏和候选栏禁学生命周期；
该入口修复前，合成繁体词“史詩”从第 4 位升到首位，补齐策略同步后不再升权。

测试已分别在原实现、只修路由的实现上失败，原因分别是中文组合为空和私密输入被学习。
完整修复后的同一回归通过；干净固定源应用、重复应用字节一致和错 revision 拒绝均有证据。
逐设备与构建结果见本地 `docs/testing/2026-11-02-S1搜狗更新词库离线对照/`。

此保护覆盖 librime 内置 Memory 写入路径及轻语现有 SDK 学习入口，不为外部自定义原生
插件提供新的信任保证。基础词库与默认普通输入行为不变；后续升级 librime 须重验补丁锚点
和上述用户可观察契约。
