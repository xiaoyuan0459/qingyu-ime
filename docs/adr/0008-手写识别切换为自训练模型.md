# 手写识别切换为自训练模型（OFL 字体合成语料）

- 状态：已实施（2026-10-23）
- 取代：[ADR 0005](0005-PP-OCRv6手写识别接入方案.md) 的引擎选择部分
- 关联：`imesdk/docs/手写识别开源迁移实施计划.md` A 轨、`tools/handwriting/README.md`

## 结论

手写识别不再使用 HCCR（3,755 类、CASIA HWDB1.1 派生权重）与 PP-OCRv6（文本行 CTC，仅作可选生僻字候选）。
改为项目自训练的 **27,664 类单字闭集分类器**，语料只由 8 个 OFL-1.1 字体离线渲染生成。

| | 旧：HCCR | 旧：PP-OCRv6 | 新：qingyu-hw-image-v1 |
| --- | --- | --- | --- |
| 形态 | 闭集分类 | 文本行 CTC | 闭集分类 |
| 类别 | 3,755 | 18,708（15,565 汉字） | **27,664**（27,584 汉字 + 80 标点/ASCII） |
| 体积（int8） | 4.09 MB | 10.07 MB | **8.05 MB** |
| 授权 | 权重为 CASIA 派生，不可随包分发 | 手写能力同样源自 CASIA，只能离线对照 | 自有语料，可分发 |

净体积变化：`8.05 − 4.09 − 10.07 = −6.11 MB`。

## 为什么不是 OCR

PP-OCRv6 的输入是 `3×48×320` 的文本行，设计目标是一行字。手写键盘一次只输入一个字，
右侧宽度绝大部分是 padding，CTC 解码在算空白；为了补几个生僻字候选付了整行识别的成本。
它同时还是默认关闭的实验开关——绝大多数用户不会打开，模型却照样占包。

单字输入的正确形态是闭集分类：输出就是该类别的概率，Top-K 直接可用，不需要序列解码。

## 语料与许可

- 来源：`tools/handwriting/fonts.json` 登记的 8 个 OFL-1.1 字体（Ma Shan Zheng、Zhi Mang Xing、
  Long Cang、Liu Jian Mao Cao、LXGW WenKai、Klee One、Noto Sans/Serif SC），下载后锁 SHA-256。
- 不使用网络抓图：授权链不可追溯，且图片口径与 `preprocess.c` 对不上。
- 不使用 CASIA/HWDB/OLHWDB：不可再分发。
- 字体本身不随包分发，只用于生成训练图像；训练配置、随机种子、字表哈希随模型资产归档。

## 模型与指标

- 结构：7 层 conv-bn-relu + GAP + FC，8.25M 参数；输入 64×64 灰度，输出 27,664 维 logits。
- 训练：RTX 4060 Laptop，width 32，batch 512，20 轮，约 45 分钟。
- 数据：666,375 张（12 种字形风格 × 平均 24 张/字），增强含弹性形变、**笔画独立位移**、
  笔宽、断笔、墨水洇染、笔压不均、墨水浓度。
- 指标（留出字体 Long Cang，完全不参与训练；干净测试集）：

| 指标 | fp16 | int8 |
| --- | --- | --- |
| Top-1 | 0.890 | 0.884 |
| Top-5 | 0.970 | 0.967 |
| Top-10 | 0.980 | 0.980 |

同字体验证集 0.999 是记忆分数，不作为泛化依据。

### 数据管线的一个已修缺陷（记录在此，避免重犯）

第一版 `augment.tone()` 用 `arr * gain` 整图乘增益，`gain` 最低 0.75 会把**背景**从 255 压到 191。
`preprocess.c` 以 `gray < 220` 判定前景，于是背景被当成笔画，bbox 退化为全画布，字形被缩到 56 px
塞进灰底——**62.7% 的训练样本是这种畸形图**，而真机推理时背景恒为纯白，训练与推理口径分叉。

该缺陷会让离线指标虚高：旧模型在「同样畸形」的测试集上有 0.895，看起来比新模型好，
但换到干净测试集只有 0.884，且在新测试集上崩到 0.223。修正后改为只调制笔画浓度
（`255 - ink*gain`），背景恒为 255。

教训：增强算子只要动到「背景/前景」的灰度边界，就必须和 `preprocess.c` 的阈值一起验证，
不能只看增强后的图「像不像手写」。

## 集成改动

- 资产：`imesdk/src/main/assets/handwriting/qingyu-hw-image-v1/`（param/bin/charset/manifest），
  由 `tools/handwriting/publish-model.py` 生成。
- 运行时：`QingyuHwRecognizer` + `qingyu_hw_jni.cc` → `libqingyu_hw_jni.so`；JNI 仍是
  `in0`/`out0` + 64×64 + softmax Top-K，`preprocess.c` 未改动。
- 字表校验：加载时强校验 `num_classes` 与 `classes` 长度一致、`classes_sha256` 匹配，
  不匹配直接初始化失败（宁可手写不可用，也不带错表输出错字）。
- 移除：`HCCRRecognizer`、`PpOcrV6Recognizer`、`PpOcrInput`、`ppocr_jni.cc`、`hccr_jni.cc`、
  两份旧模型资产、设置页「生僻字候选（实验）」开关及其文案。

## 已知风险

1. **真手写未验证。** 0.898 是「未见过的字体」，不是「真人笔迹」。字体没有连笔、笔顺错误、
   个人习惯，域差真实存在。上线前必须用真人样本做基准（见下）。
2. **生僻字跨风格样本缺口。** 留出字体 Long Cang 只覆盖 6,842 字，扩展区生僻字没有跨风格测试样本，
   其 0.861 的分频段指标只覆盖 GB2312 内的低频字。
3. **模型体积。** 8.05 MB 是当前最大单项资产，已通过 int8 压到目标区间；再压需 QAT。

## 回滚

旧资产与旧代码在 git 历史中可恢复，但**不得以重新打包 CASIA 派生权重作为回滚方案**（同 ADR 0005 §10）。
新引擎不可用时，合法回滚形态是「发布版不带手写」。
