# ADR 0003：候选展示筛选与只读笔画反查

日期：2026-10-08。状态：已实施。

## 场景与决定

用户要求保留轻语的候选排序，吸收搜狗展开页的格线、首选高亮，以及右侧返回、退格、重输、拼音／笔画、全部／单字操作。

展示层使用 `CandidatePanelState.Entry(engineIndex, text)` 投影现有候选列表，筛选保留引擎顺序与原始下标。点击和默认确认使用原始下标；无匹配结果时不选择隐藏候选。单字以 Unicode 码点和汉字区块判断，兼顾扩展汉字。格子按可用宽度和字体缩放使用 2～4 列，第一项只改变颜色。

对照当前安装的魅族搜狗后，笔画确定为当前拼音候选首字的起笔单选，不切换正在输入的 Rime 方案。左栏提供横、竖、撇、点、折；重复点击同一笔保持选择，点另一笔替换选择并恢复全部候选，选起笔后再开单字可组合筛选。右侧退格直接删除组合并清除筛选。返回保留组合和笔画／拼音模式，清除起笔与单字选择；重输清除未上屏组合并回键盘。切输入框和输入状态重置清除筛选，配置重建由 InputView 持有当前状态。

左右操作栏均分五段，当前起笔有底色；模式标签采用斜分排布、当前项较大／较深，字号和退格图标受行高约束。实测搜狗在 560 dpi／1.3 系统字体下仍为四列且字形尺寸不变；轻语保留候选主文字的系统大字支持，网格允许减列，侧栏保持比例。该取舍兼顾参考的视觉层级与已有字号设置。

## 数据与原生边界

复用已分发词库的 `build/stroke.reverse.bin`，不新增数据、依赖、下载或权限。现有来源及许可仍以词库 pack 的 SOURCE、manifest 和 LICENSING 为准。

上游 C API 未提供直接只读反查入口。`stroke_lookup.cc` 独立使用固定 librime 1.11.2 的 `rime::ReverseDb` 类型，打开局部只读映射，按字返回空格分隔的编码。它不访问输入会话，不改变选项、排序或用户词库。该 C++ 类型与二进制格式存在版本耦合，不能仅凭 C API 兼容就认定可升级；升级 librime 或词库编译器时必须重建并运行反查设备测试。没有修改第三方源码或引入私有分叉。

Kotlin 边界只接收每批最多 128 个单汉字；JNI 使用最多 1024 字节的标准 UTF-8 ByteArray，避免补充平面字符被 JNI modified UTF-8 改写。路径由当前包目录和固定文件名生成，不接受 UI 传入的路径。返回长度须匹配请求；缺失、不可读的反查资料显示重试入口，拼音模式仍可用。

## 生命周期与失败处理

IO 在线程池执行，每次查询只打开当前基础包文件，2.5 秒超时转入可重试失败状态。结果应用时检查请求序号、展示状态修订号、引擎代次、窗口可见性和输入暂停状态。面板隐藏或脱离窗口取消任务；取消和超时不强行中断正在执行的有界 native 调用，完成后丢弃过期结果。临时反查缓存只属于当前 InputView，重置和引擎代次变化时清空，不落盘或记录输入内容。

候选分页仍通过现有累计列表追加，页面数据在主线程发布，保留全局下标。筛选自动补最多三页；不足一屏且仍有下一页时显示“继续查找”，其余由滚动继续读取，避免无限后台遍历或无法继续查找。

## 验证

`CandidatePanelStateTest` 验证单字／笔画组合筛选、原始下标、分页累计、扩展汉字及状态重置。`CandidateStrokeLookupTest` 在 Android 上读取现有真实反查表，并核对活动方案、简繁、组合与候选未变化。视觉和右侧操作通过模拟器交互另行记录在[界面与交互](https://github.com/xiaoyuan0459/qingyu-ime/wiki/UI-and-Interaction)，构建成功不能代替设备验收。截图和完整单次报告只留在本地忽略目录。
